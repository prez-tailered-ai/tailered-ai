# ADR-005: Decline Ruflo v3.37.0 as an execution substrate

## Context

Audit `AUD-RUFLO-20260811-221322` (merged evidence corpus at `docs/audits/ruflo/AUD-RUFLO-20260811-221322/`) evaluated Ruflo (`ruflo@3.37.0`, implemented by `@claude-flow/cli@3.37.0`, GitHub `ruvnet/ruflo` at `6ce18b5a7fcd4939a2f72c2e3b8fdbdec660e5a9`, MIT) as a candidate subordinate execution substrate for the Tailered AI agent platform. The audit ran thirteen bounded investigation lanes against a frozen baseline with every piece of Ruflo code executed in disposable containers that never mounted host credentials. The overall verdict is `NOT_QUALIFIED`: 212 findings were recorded (33 CRITICAL, 72 HIGH, 66 MEDIUM, 20 LOW, 21 INFO), 42 of Ruflo's 90 capability claims were refuted, zero capabilities reached the DURABLE maturity rung, and the audit's central lesson — a reported success is only a claim until a separate mechanism verifies the resulting state — was violated repeatedly by Ruflo's own verification, persistence, coordination, and cleanup paths. The audit's `proposed-adr.md` deliberately declined to claim a decision number, because ADR numbering and acceptance are the founder's acts. Since the audit merged, P0-A closed the agent write-containment boundary, P0-B closed the ledger-concurrency and crash-recovery defects the audit exposed in this repository itself (PR #7, R1-R8 and A1-A7 all `VERIFIED`), and `ADR-004` recorded the Hermes-Honcho reference-architecture decision, taking the number the audit draft could not reserve. This decision therefore takes the next number available on current `main` and formalizes the disposition the audit recommended.

## Decision

Decline Ruflo v3.37.0 as an execution substrate. Ruflo is `NOT_QUALIFIED`. Ruflo is not authorized for installation, integration, agent construction, or deployment. No Ruflo package, plugin, MCP server, daemon, router, memory database, workflow engine, proxy, verification system, background worker, or deployment component is authorized in `prez-tailered-ai/tailered-ai` or on any infrastructure this repository governs. Tailered may independently implement selected design patterns that the audit assessed favorably — the four reimplementation candidates named in the audit's final recommendation — and independent implementation grants no authority to Ruflo code, packages, services, or configurations. Ruflo remains an external read-only reference. Requalification requires a later pinned release and a complete new audit against the revisit criteria in `16-final-recommendation.md`. This decision authorizes no production deployment of anything.

## Alternatives rejected

- Adopt Ruflo as the execution substrate: refuted by 33 CRITICAL findings, including a publicly derivable verification signing seed, non-functional consensus, and a cleanup path that reverts 21.7 percent of its own changes.
- Adopt Ruflo partially (memory, routing, or observability only): every partial mode still installs the unqualified runtime and its false-success reporting surface.
- Copy Ruflo source into this repository: imports the same defects while severing the upstream fix path, and violates the zero-runtime-dependency posture.
- Defer the decision without recording it: leaves an audited, refuted system formally undecided and invites drift; the audit corpus already carries the evidence this record rests on.

## Consequences

- Ruflo remains a rejected, read-only external reference; the audit corpus under `docs/audits/ruflo/AUD-RUFLO-20260811-221322/` is the immutable evidence base for this decision.
- The four favorably assessed ideas may be reimplemented natively, each under its own future decision and evidence, with no Ruflo code or authority attached.
- The P0-B foundation (locked transactions, durable allocation, intent-first finalization, recovery, quarantine) is the platform Tailered builds agent workflows on instead.
- Requalification of any future Ruflo release requires a new pinned audit; nothing in this decision expires into permission.
- Acceptance of this decision is a founder act; until PREZ accepts it, its on-disk status stays `proposed`.
