# ADR-001: Fix the v1 executable contract

## Context

The v1 pseudocode left terminal failure rows, budget boundaries, router signals, platform-versus-product auth scope, ADR supersession, and edit-gate DoD behavior ambiguous.

## Decision

Every run writes one terminal eval with an explicit outcome. Gate labels are conditional. Cost uses reserve/settle with an exclusive five-dollar cap. Routing receives attempt signals without state. Supersession appends a typed edge. The gating demo is a single-user todo app and requires approve with zero edits.

## Alternatives rejected

- Drop halted and rejected runs from the evaluation corpus.
- Enforce the budget only after cost is incurred.
- Treat a product auth requirement as platform multi-user authentication.

## Consequences

- Failure and rejection remain first-class data for tokens-per-outcome and preference analysis.
- The non-gating auth benchmark may green or halt without blocking v1.
- Dashboard status for superseded decisions is derived without modifying old files.
