# ADR-003: Adopt the staged full-system blueprint

## Context

Tailered needs a complete architectural trajectory without allowing later-stage ideas to expand the contracted v1 surface. The v1 runtime also lacked exact call replay data, measurable context-cache behavior, and a runtime connection to its repository model registry.

## Decision

Adopt the Full-System Blueprint under the precedence order v1 contract for scope, Platform Brief for intent, and blueprint for trajectory. Execute its v1 foundations by loading model identity from the repo registry, storing shared context snapshots and exact call traces, measuring context movement, and preserving accounting violations before terminal halt.

## Alternatives rejected

- Treat every subsystem in the blueprint as immediate build authorization.
- Store only terminal summaries and reconstruct historical model inputs later.
- Keep model aliases compiled into routing code while also presenting the repo config as authoritative.
- Duplicate terminal outcomes into a second physical v1 ledger.

## Consequences

- Later systems receive replay, routing, context, label, and outcome data without entering v1 scope.
- Model upgrades are repository string swaps.
- Context economics and failed accounting calls are measurable rather than inferred.
- Post-v1 systems remain refused until their blueprint data gates are verified.
